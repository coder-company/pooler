# Product Goal

Build and release Pooler as a production-grade, cross-platform Rust protocol runtime that fulfills every in-scope requirement and phase exit criterion in `ARCHITECTURE_PLAN.md`: one reproducible binary must replace the existing Cursor, Factory/effects, and Devin bridges; expose arbitrary custom, OpenAI, Anthropic, Gemini, Amp, protobuf/ConnectRPC, SSE, and WebSocket layouts concurrently without requiring a global client personality or mandatory semantic adapter; support independently composable opaque, inspect, patch, and semantic route plans; preserve protocol-specific tools, media, reasoning state, identifiers, usage, errors, and terminal stream semantics according to explicit reject/preserve/degrade policies; provide secure multi-provider credential pooling, OAuth refresh coordination, capability-aware routing, session affinity, bounded retries, correctly scoped cooldowns, hot-reloaded immutable configuration, overlays, SQLite persistence, diagnostics, management APIs, observability, sanitized record/replay conformance, and a sandboxed extension boundary. Completion requires all workspace formatting, Clippy, unit, integration, differential, property, failure-injection, concurrency, security, dependency, license, and platform CI checks to pass; 100% of committed compatibility fixtures to pass with zero unexplained semantic differences; no retry after downstream commitment and no credential cooldown from request-invalid failures in the full fault corpus; verified cancellation with no leaked tasks, permits, refresh leases, temporary files, or secret material; zero known critical or high-severity vulnerabilities; secret-redaction and owner-only credential-storage tests to pass; Linux x86_64/ARM64 and macOS ARM64/x86_64 release artifacts, checksums, signatures, SBOM, configuration schema, and compatibility report to be produced; opaque loopback overhead to remain below 2 ms p95 and semantic translation below 5 ms p95 for a 1 MiB request across three consecutive documented benchmark runs; and a reproducible 15-minute mixed-protocol stress test to process at least 10,000 requests at 100 concurrent clients with 20% deterministic injected upstream failures, zero crashes, deadlocks, invariant violations, or incomplete successful streams, all tracked tasks, permits, refresh leases, and temporary files returning to zero after drain, and post-drain RSS no more than 10% above the measured post-warmup baseline. Keep implementation within the architecture’s modular-monolith, composable-route, explicit-loss, immutable-plan, and sandboxed-extension boundaries; do not claim unsupported provider compatibility or evade provider enforcement. Stop and ask for a decision only when required protocol evidence, credential authorization, licensing rights, provider terms, or a product choice would materially alter public behavior, security, compatibility, or scope and cannot be resolved from the repository, sanitized fixtures, existing local adapters, or authoritative provider documentation.
